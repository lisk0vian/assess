# Anti-cheat methods and limits

`ax` makes cheating harder and leaves a record for you to review. It cannot
prevent every kind of cheating. Read [Limits](#limits) before you rely on it for
a high-stakes exam.

It uses only what a web browser exposes. There is no webcam, no microphone, no
lockdown browser and nothing to install. It reads nothing outside the exam tab.

Students see what is recorded and what each thing costs before they start.
Automatic penalties are signals for you, not verdicts, and you can revert them.

## Profiles

Set the profile in `manifest.yaml`:

```yaml
proctoring:
  profile: standard   # off | standard | strict
```

`standard` and `strict` turn on the same protections and differ in tolerance.
`off` turns everything off.

| What happens | `standard` | `strict` |
|---|---|---|
| Away from the tab | Warning from 3 s. After 10 s, a strike and −20 % of the remaining time | Warning from 1.5 s. After 3 s, a strike and −50 % of the remaining time |
| Using another window | Warning from 3 s. Strike after 10 s | Warning from 2 s. Strike after 5 s |
| Leaving required fullscreen | Strike after 5 s | Strike after 3 s |
| Copying or capturing the screen | First time a warning, then a strike and the question is voided | Strike and the question is voided |
| Pasting into an answer | First time a warning, then a strike | Strike |
| Strikes that annul the exam | 3 | 2 |
| Devices | Any | Desktop only |

Only automation and forged telemetry count during the first 15 seconds. One
absence counts once, and network drops never count.

## What makes cheating harder

| Protection | What it does | Setting |
|---|---|---|
| Typed pledge | The student reads the rules and types a pledge | Part of the profile |
| Privacy curtain | The exam hides as soon as the window loses focus | Part of the profile |
| Fullscreen | The exam shows only in fullscreen | `proctoring.fullscreen` |
| Hidden options | Options appear only under the pointer or on keyboard focus. On a phone, the first tap reveals an option and the second chooses it | `proctoring.reveal` |
| Reading lens | The prompt shows a range of 4–15 words at a time | `proctoring.lens`, `auto_read`, `read_speed` |
| Watermark | The student's name and ID appear over the question | Part of the profile |
| Copy and paste blocked | Copied text is replaced by a notice | Part of the profile |
| Capture shield | The exam hides while the Windows or Command key is held. PrintScreen is replaced by a notice, and printing is blocked | Part of the profile |
| One question at a time | Questions are fetched one by one, so nothing arrives in advance | Always on |
| Shuffling and pools | Each student gets a different order or different questions | `order`, `items` |
| Timed questions | The server locks a question when its time runs out | `time_limit` |
| Server-side key | The answer key never reaches the browser, and the server does the grading | Always on |
| One tab | A second tab of the exam is blocked | Always on |
| Device control | A second device with the same ID needs your approval | Always on |

## What is recorded

| Signal | Consequence |
|---|---|
| Tab hidden, another window, fullscreen left | See the table above |
| Copy, PrintScreen, trying to print | See the table above |
| Text pasted, dropped or inserted by an extension | See the table above |
| A browser driven by automation, or clicks and keys generated by a script | Strike |
| Signed telemetry that fails verification | Strike |
| Text appearing faster than anyone types | Warning for the teacher |
| An extension injecting elements into the page | Warning for the teacher |
| The exam opened in a second tab | Warning for the teacher |
| Answers arriving while the live channel is silent | Warning for the teacher |
| Staying still, then answering | Warning for the teacher, never a strike |

Keystrokes are measured by type and speed only. Their content is not recorded.

## What the teacher can do

- See each student's strikes live, and every signal in the **Incidents** view.
- Revert a penalty with **Z**. It stays on record with your note, and the lost
  time comes back.
- Readmit an annulled student with **U**.
- Turn the lens off for one student with **V**, as an accommodation.
- Give extra time, send a message, or pause a student.

## What the report flags

`ax session report` looks for evidence after the exam. Evidence is a reason to look
closer, not proof.

- **Similar answers:** pairs of students who share unusual wrong answers, or
  who saved the same answers at the same moment on different question numbers.
- **Left and got it right:** a right answer saved just after the student came
  back to the exam.
- **Questions that became easier:** a question much easier than in earlier
  sessions of the same exam, which may have leaked.

## Limits

No browser-only system can stop a determined student. These are the known gaps.

**What `ax` cannot detect**

- **A second device.** A phone under the desk, a smartwatch or a second laptop
  leaves no trace.
- **What happens in the room.** Notes, whispering and copying from a neighbour's
  screen are invisible to it. The similar-answers report can only suggest some
  of this afterwards.
- **Who is really answering.** Students type their own name and ID, and nothing
  checks them against a person. `--roster-only` limits who gets in, but it does
  not prove identity.
- **Virtual machines and remote desktops.** They are not detected, on purpose.
- **Developer tools.** They are not detected, on purpose.

**What `ax` can only slow down**

- **Photos of the screen.** The lens and hidden options limit a photo to one range
  of the prompt or one option. An AI can often answer from the prompt alone.
- **Video of the screen.** A recording captures the whole automatic reading of
  the prompt, and every option as it is revealed.
- **Screenshots.** A web page cannot block them. Some ways are detected, but a
  capture from outside the browser is not.
- **Hidden options.** Their text is obfuscated in the browser, not encrypted.
- **Altered browsers.** The signals come from the student's browser, which also
  holds the key that signs them. Someone who changes the page or writes a custom
  client can suppress or fake signals. A silent channel raises a warning, but it
  does not prove anything.
- **Fullscreen.** It cannot be enforced on a browser without fullscreen support,
  which is common on phones. Use `devices: desktop` when fullscreen matters.

**What can go wrong for honest students**

- **False positives.** A system notification or an accidental click outside the
  window can count, so review strikes before you act on them.
- **Staying still is normal.** That is why it never counts as a strike.
- **Accessibility.** Hidden options and the lens add effort. Use **V** or an exam
  setting for students who need it.

**Network and storage**

- **No encryption on the classroom network.** Students connect over plain HTTP,
  so someone on the same network could read the traffic. Answer keys are never
  sent, but answers are.
- **The exam folder is not protected.** Anyone who can open it can read
  `private/answer-key.yaml`. Keep exams in an encrypted
  [vault](../README.md#the-vault) on a shared computer.

## How to get the most from it

- Stay in the room. Your presence is the best protection against a second device.
- Write questions that need reasoning, and vary numbers with question pools.
- Keep time tight, so looking things up costs more than it gives.
- Use `strict` only when you can review strikes the same day.
- Treat strikes and evidence as the start of a conversation with the student.
